# 导出流程

1. 用 `list_projects` 读取所有有实际本地路径的登记项目。只纳入本地可访问项目；
   记录无法访问的登记项，不扫描整块硬盘猜测项目。
2. 清点匹配的活动和归档任务。优先通过官方 app-server 的分页历史接口直接写入
   原始记录文件，使用 `capture_context.py --codex-command <可用 Codex CLI>
   --project <根目录> ... --output <暂存/context.json>`。该程序只调用读取接口，
   不启动任务、不复制内部账号或会话存储。将返回的任务 ID 与 app 工具清点结果比较。
   若 CLI 不可用，使用可用的 `list_threads`、`read_thread` 及分页游标采集，
   写出 coverage、warnings 和缺失任务 ID；不得以时间预算静默退化为完整采集成功。
3. 用 `inventory --projects-file <清单> --codex-context <记录> --codex-home <实际路径>
   --agents-home <实际路径>` 得到全量项目、链接依赖、可识别引用资产、白名单配置。
   检查清单中的外部目录；目录依赖在当前文件权限范围内读取。将结果保存为 projects.json。
   素材的路径可能埋在工具输出中；无法确定的引用写进缺失清单，不虚构路径。
4. 每个重要未完成任务附带有来源的续接说明：用户目标、决定、已完成项、剩余项、
   关键资产路径和下一步。原始记录保留；摘要不替代历史。默认不读取认证存储。
5. 自动选用源目录之外的持久输出目录，优先非系统盘并检查总空间。
   已存在迁移包不覆盖；内部运行 export --dry-run 检查路径集合后直接导出。

```powershell
python scripts/codex_migrate.py pack --projects-file <清单> --codex-context <记录> --output <包.pyz>
```

默认 auto 使用低等级 zlib 原生并行压缩，已压缩媒体选择直接存储。用户不用选择技术参数。
导出自身完成最终验包，不要再立即重复读取整个包验证。

- 中断继续：同一输出加 `--resume`；源目录或上下文变化时需要新输出名称。
- 增量复用：`--base-package <schema3旧包>`。新包包含所有所需块，独立恢复，
  不依赖携带旧包。源文件仍读取并计算哈希，避免把时间戳当作完整性证明。
- 加密导出：`--encrypt`，可附 `--key-file <密钥路径>`。未提供时自动生成恢复密钥，
  输出仅显示密钥文件路径。说明密钥单独保管，否则无法在新电脑解密。
- “开始部署.cmd”和对应 ps1 与包放在同目录一起搬运；入口根据自身位置传入新路径。
- 用实际个人市场 ID 填 `--plugin-identity`；不同电脑插件 ID 变化时可用 @ 手动选择。

最终给出包路径、部署入口、项目/资源/环境项数量、逻辑大小与包大小、完整性结果、
原始任务记录覆盖率、缺失项、加密状态及恢复密钥位置。没有联网传输。
